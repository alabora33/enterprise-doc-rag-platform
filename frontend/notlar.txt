  Tailwind CSS:
    → Ayrı CSS dosyası yazmadan bileşen üzerinde stil uygulanır.
    → className="flex items-center gap-4" → doğrudan utility sınıfları.
    → Tasarım tutarlılığı: her renk, boşluk, radius scale'den geliyor.

FRONTEND — api/axiosClient.js
========================================================

## NE YAPAR?

Tüm API isteklerinde kullanılacak merkezi Axios örneği oluşturur.
Token ekleme işini tek noktadan yönetir.

## KOD ANALİZİ

  const axiosClient = axios.create({
    baseURL: "http://localhost:8000/api/v1",
  });

  → baseURL: her istekte tam URL yazmak yerine sadece
    "/auth/login" gibi path yazılır.
  → Backend port 8000'de çalışıyor (FastAPI).
  → Prodüksiyona geçince bu URL environment variable olmalı
    (örn: VITE_API_URL). Şu an hardcoded — geliştirme aşaması.

  axiosClient.interceptors.request.use((config) => {
    const token = localStorage.getItem("access_token");
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
    return config;
  });

  → interceptors.request.use: her istek gönderilmeden önce çalışır.
  → localStorage.getItem("access_token"): login sonrası kaydedilen JWT.
  → Token varsa Authorization: Bearer <token> header'ı eklenir.
  → Token yoksa header eklenmez — login sayfası gibi public
    endpoint'ler hata almaz (backend zaten token gerektirmez).
  → Bu interceptor olmadan her API çağrısında manuel header eklenmek
    zorunda kalınırdı: 10 endpoint = 10 tekrar eden kod.

## GÜVENLİK NOTU

  localStorage kullanımı XSS saldırılarına karşı zayıf bir noktadır.
  XSS ile kötü niyetli script token'ı okuyabilir.
  Daha güvenli alternatif: httpOnly cookie (JavaScript erişemez).
  Şu an geliştirme kolaylığı için localStorage tercih edilmiş.
  Üretime geçmeden cookie tabanlı auth'a geçilmeli.

FRONTEND — components/ProtectedRoute.jsx
========================================================

## NE YAPAR?

Kimlik doğrulama gerektiren sayfaları token yoksa otomatik
/login'e yönlendiren wrapper bileşeni.

## KOD ANALİZİ

  export default function ProtectedRoute({ children }) {
    const token = localStorage.getItem("access_token");

    if (!token) {
      return <Navigate to="/login" replace />;
    }

    return children;
  }

  → localStorage'da "access_token" yoksa: /login'e yönlendir.
  → replace: tarayıcı geçmişine bu yönlendirme eklenmez.
    Kullanıcı "geri" tuşuna basınca korumalı sayfaya dönemez.
  → Token varsa: children (korunan içerik) render edilir.

  BASİT AMA YETERLİ NEDEN?
  → Token varlığı kontrol ediliyor, geçerliliği değil.
  → Süresi dolmuş token localStorage'da olsa da ProtectedRoute geçer.
  → Gerçek geçerlilik kontrolü API isteği yapılınca backend'de olur:
    401 döner → kullanıcı login'e yönlendirilebilir (henüz implemente değil).
  → Tam uygulama için: token decode edip exp claim kontrol edilmeli
    veya 401 response'u yakalayan response interceptor eklenmeli.

## KULLANIM YERİ — App.jsx

  <Route
    element={
      <ProtectedRoute>
        <DashboardLayout />
      </ProtectedRoute>
    }
  >
    <Route path="/dashboard" element={<DashboardPage />} />
    <Route path="/documents" element={<DocumentsPage />} />
    <Route path="/chat"      element={<ChatPage />} />
  </Route>

  → Bir ProtectedRoute tüm korumalı sayfaları kapsar.
  → DashboardLayout'un içine render olan tüm alt sayfalar
    otomatik olarak korunmuş olur. Her sayfaya ayrı ayrı
    ProtectedRoute sarmak gerekmez.

FRONTEND — App.jsx — ROUTING YAPISI
========================================================

## KULLANILAN YAPI: BrowserRouter + Routes

  <BrowserRouter>
    <Routes>
      <Route path="/login" element={<LoginPage />} />

      <Route element={<ProtectedRoute><DashboardLayout /></ProtectedRoute>}>
        <Route path="/dashboard" element={<DashboardPage />} />
        <Route path="/documents" element={<DocumentsPage />} />
        <Route path="/chat"      element={<ChatPage />} />
      </Route>

      <Route path="*" element={<Navigate to="/dashboard" replace />} />
    </Routes>
  </BrowserRouter>

## ROUTE YAPISI NEDEN BÖYLE?

  Layout Route (parent) + Alt Routelar (children):
  → Ortak yapı (sidebar, nav) DashboardLayout'ta tek kez tanımlanır.
  → Her sayfa sadece kendi içeriğini yazar, layout tekrar etmez.
  → React Router v7'de Outlet bileşeni alt route'un nereye
    render olacağını belirler. DashboardLayout içinde <Outlet />
    vardır.

  path="*" — Catch-all:
  → Tanımlı olmayan herhangi bir URL → /dashboard'a yönlendirir.
  → 404 göstermek yerine uygulama kullanıcıyı ana sayfaya götürür.
  → replace: tarayıcı geçmişinde bilinmeyen URL kalmaz.

  /login public, gerisi private:
  → /login route'u ProtectedRoute dışında → token olmadan görünür.
  → Diğer tüm route'lar ProtectedRoute içinde → token zorunlu.

## SAYFA AKIŞI

  Uygulama açılır → path "/" yoktur → "*" → /dashboard'a yönlendir
  /dashboard → ProtectedRoute → token var mı?
    → Hayır: /login'e yönlendir
    → Evet: DashboardLayout render → DashboardPage içerik alanına

FRONTEND — pages/LoginPage.jsx
========================================================

## NE YAPAR?

Email + şifre ile giriş formunu render eder. Başarılı girişte
JWT token'ı localStorage'a kaydeder ve /dashboard'a yönlendirir.

## STATE YÖNETİMİ

  const [email, setEmail]       = useState("testorg@example.com");
  const [password, setPassword] = useState("1212123");
  const [error, setError]       = useState("");
  const [loading, setLoading]   = useState(false);

  → email / password: kontrollü input (controlled component).
    Input'un değeri her zaman state ile senkronize.
  → error: API hata mesajı göstermek için.
  → loading: buton disabled + metin değişimi için.
  → useState("testorg@example.com"): geliştirme kolaylığı için
    test kullanıcısı varsayılan olarak girilmiş. Prodüksiyonda
    boş string olmalı.

## GİRİŞ AKIŞI — handleLogin

  event.preventDefault()
    → Form submit → tarayıcı sayfayı yenilemesin.

  const formData = new URLSearchParams();
  formData.append("username", email);
  formData.append("password", password);

  → Backend OAuth2PasswordRequestForm bekliyor.
  → OAuth2 standardı: login endpoint'i
    application/x-www-form-urlencoded formatı alır. JSON değil.
  → Alan adı "username" — email gelse de OAuth2 standardı böyle der.
  → URLSearchParams: form-encoded data üretir.
    {"username": "ali@x.com", "password": "123"} değil,
    "username=ali%40x.com&password=123" formatı.

  axiosClient.post("/auth/login", formData, {
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
  });

  → axiosClient varsayılan olarak JSON gönderir.
  → Bu istek için Content-Type override ediliyor.
  → Backend FastAPI OAuth2PasswordRequestForm ile doğru parse eder.

  localStorage.setItem("access_token", response.data.access_token);
  navigate("/dashboard");

  → Token kaydedilir.
  → useNavigate hook'u ile programatik yönlendirme.

## i18n/i18n.js

  import i18n from "i18next";
  import { initReactI18next } from "react-i18next";
  import tr from "./locales/tr.json";
  import en from "./locales/en.json";

  const savedLanguage = localStorage.getItem("language") || "tr";

  i18n.use(initReactI18next).init({
    resources: { en: { translation: en }, tr: { translation: tr } },
    lng: savedLanguage,
    fallbackLng: "tr",
    interpolation: { escapeValue: false },
  });

  → localStorage "language" anahtarı ile dil tercihi kalıcı.
  → Sayfa yenilense bile kullanıcının seçtiği dil korunur.
  → fallbackLng: çeviri anahtarı bulunamazsa Türkçe'ye düşer.

FRONTEND — components/Toast.jsx — TOAST BİLDİRİM SİSTEMİ
========================================================

## NEDEN OLUŞTURULDU?
Önceden doküman işlemleri başarı/hata durumlarını satır içi
div element'leri ile gösteriyordu. Bu UI açısından sorunluydu:
  - Hata mesajı sayfada kalıcı olarak görünürdü.
  - Kullanıcı mesajı okumasa da form alanını kapatırdı.
  - Birden fazla mesaj bir arada görüntülenemezdi.

Toast sistemi ile:
  → Mesajlar sağ üstte (fixed top-5 right-5) kayar şekilde çıkar.
  → 4 saniye sonra otomatik kapanır.
  → Kullanıcı isterse X ile manuel kapatır.
  → Birden fazla mesaj üst üste yığılır.

## DIŞ AKTARIMLAR (export)

  Toast       : Tekil toast bileşeni (internal kullanım)
  ToastContainer : Tüm toast'ları render eden wrapper
  useToast    : State yönetimi hook'u

## useToast() HOOK'U

  const { toasts, addToast, removeToast } = useToast();

  addToast(message, type)
    → type: "success" | "error" | "info"
    → Her çağrıda benzersiz ID üretir (Date.now())
    → 4 saniye sonra setTimeout ile otomatik removeToast çağırır

  removeToast(id)
    → Belirtilen toast'ı listeden çıkarır

## KULLANIM

  import { ToastContainer, useToast } from "../components/Toast";

  function MyPage() {
    const { toasts, addToast, removeToast } = useToast();

    return (
      <>
        <ToastContainer toasts={toasts} onClose={removeToast} />
        <button onClick={() => addToast("Başarılı!", "success")}>
          Tıkla
        </button>
      </>
    );
  }

## GÖRSEL TASARIM

  Konumu  : fixed right-5 top-5 z-50
  Boyutu  : w-80 (320px sabit genişlik)
  Animasyon: slide-in-from-right (Tailwind animate)
  Renkler :
    success → yeşil (bg-green-50 border-green-500 text-green-800)
    error   → kırmızı (bg-red-50 border-red-500 text-red-800)
    info    → mavi (bg-blue-50 border-blue-500 text-blue-800)

FRONTEND — components/ConfirmModal.jsx — SİLME ONAYI
========================================================

## NEDEN OLUŞTURULDU?
window.confirm() tarayıcının native dialog'unu açar.
Bu dialog:
  → Tailwind ile stil uygulanamaz.
  → Türkçe/İngilizce metin kontrolü yoktur.
  → Modern UI beklentisini karşılamaz.
  → Bazı tarayıcılarda devre dışı bırakılabilir.

ConfirmModal ile:
  → Tam ekran blur backdrop (bg-black/50)
  → Kırmızı uyarı ikonu (Heroicons ExclamationTriangle)
  → i18n ile çevrilebilir başlık ve mesaj
  → ESC tuşu + backdrop tıklaması ile iptal

## PROPS

  title     : string  → Modal başlığı (örn: "Belgeyi Sil")
  message   : string  → Açıklama (örn: "Bu işlem geri alınamaz.")
  onConfirm : () => void → Onayla butonuna basılınca çalışır
  onCancel  : () => void → İptal butonuna veya ESC/backdrop'a basılınca

## KLAVYE DESTEĞI

  useEffect(() => {
    const handleKeyDown = (e) => {
      if (e.key === "Escape") onCancel();
    };
    document.addEventListener("keydown", handleKeyDown);
    return () => document.removeEventListener("keydown", handleKeyDown);
  }, [onCancel]);

  → ESC tuşu ile modal kapatılır.
  → Cleanup: bileşen unmount olunca event listener kaldırılır.
    Bellek sızıntısı olmaz.

## KULLANIM — DocumentsPage.jsx

  const [confirmDeleteId, setConfirmDeleteId] = useState(null);

  {confirmDeleteId && (
    <ConfirmModal
      title={t("documents.deleteConfirmTitle")}
      message={t("documents.deleteConfirm")}
      onConfirm={handleConfirmDelete}
      onCancel={() => setConfirmDeleteId(null)}
    />
  )}

  → confirmDeleteId null ise modal render edilmez.
  → handleDelete(id) çağrılınca confirmDeleteId set edilir → modal açılır.
  → handleConfirmDelete() gerçek silme işlemini yapar.

## YAPILAN DEĞİŞİKLİKLER

### 1. setError BUG DÜZELTME (KRİTİK)

  Önceden: setError("") çağrısı üç farklı fonksiyonda vardı.
  Sorun   : "error" state hiç tanımlanmamıştı (useState ile).
  Sonuç   : "setError is not defined" runtime hatası → sayfa
            çalışmıyordu, doküman listesi yüklenmiyordu,
            yükleme yapılamıyordu.
  Çözüm   : Tüm setError("") çağrıları kaldırıldı.
            Hata gösterimi artık tamamen toast sisteminde.

  Etkilenen fonksiyonlar:
    → fetchDocuments()          → setError("") kaldırıldı
    → handleUpload()            → setError("") kaldırıldı
    → handleViewChunks()        → setError("") kaldırıldı

### 2. TOAST BİLDİRİMLERİ

  Tüm başarı ve hata mesajları artık toast ile gösteriliyor:
    addToast(t("documents.errors.fetchDocuments"), "error")
    addToast(t("documents.uploadSuccess"), "success")
    addToast(t("documents.deleteSuccess"), "success")
    addToast(t("documents.retrySuccess"), "success")
    addToast(t("documents.errors.uploadFailed"), "error")
    vs.

  Avantajı: Mesajlar 4 sn sonra kaybolur, sayfa temiz kalır.

### 3. CONFIRM MODAL İLE SİLME

  Önceden: window.confirm() → tarayıcı native dialog'u
  Şimdi  : ConfirmModal bileşeni → özel tasarımlı onay ekranı

  handleDelete(id)     → confirmDeleteId set eder → modal açılır
  handleConfirmDelete()→ asıl silme API çağrısını yapar

### 4. DURUM ÇEVİRİLERİ

  Türkçe'de → "Yüklendi", "İşleniyor", "Tamamlandı", "Başarısız"

### 5. KÜÇÜK DÜĞME BOYUTLARI
